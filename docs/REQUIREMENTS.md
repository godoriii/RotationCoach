> 상태: 기획 초안 v0.1 (2026-10-16) · 승인 전 구현 금지
> 관련 문서: [ARCHITECTURE](ARCHITECTURE.md) · [TECH_DECISIONS](TECH_DECISIONS.md) · [SCORING_SPEC](SCORING_SPEC.md) · [RISKS](RISKS.md) · [SPIKES](SPIKES.md) · [ROADMAP](ROADMAP.md)

## 0. 확정된 전제 (사용자 답변 반영)

| 항목 | 결정 |
|---|---|
| 게임/버전 | WoW 리테일 한밤(Midnight, 12.x) |
| 대상 전문화 | 생존 사냥꾼 1개. 구조는 다른 전문화로 확장 가능해야 함 |
| 영웅 특성 | **무리의 지도자(Pack Leader)·파수꾼(Sentinel) 둘 다** 엔진에서 지원. 실측 검증은 주로 쓰는 쪽부터 |
| MVP 콘텐츠 | **단일 대상 우선**: 허수아비, 레이드 보스 단일 구간. 광역·쐐기는 MVP 이후(M7) |
| 사용자 | **본인 1인 전용**. 공개 배포·설치 관리자·다중 사용자 지원은 하지 않음 |
| 실행 환경 | Windows 10/11 PC, WoW는 창 모드(전체 화면, borderless) |
| 구현 언어 | 추천안 따름 → [TECH_DECISIONS §1](TECH_DECISIONS.md#1-구현-언어와-런타임) (Python 단일 언어 추천) |
| 표시 시점 | **풀(전투) 종료 직후 채점·표시가 주 모드.** 전투 중 갱신은 로그가 실제로 도착할 때만 동작하는 부가 기능이며 기본값은 꺼짐 (아래 설명, [결정 D-3](#6-결정이-필요한-항목)) |

> **왜 "풀 종료 직후"가 주 모드인가.** WoW는 패치 10.2부터 전투 로그를 전투 중 메모리에 모았다가 전투가 끝날 때 몰아서 기록한다고 보고됐고, Blizzard는 2023-08-21 블루 포스트에서 고급 전투 로그를 게임 밖 실시간 오버레이에 쓰지 못하게 바꾸겠다고 밝혔다 ([RISKS T-1, P-1](RISKS.md)). 따라서 전투 중 실시간 채점은 (1) 기술적으로 데이터가 안 올 가능성이 높고 (2) 데이터가 오더라도 Blizzard의 의도에 반한다. 이 도구의 가치는 **"풀이 끝나자마자 게임 화면 위에서 바로 보는 채점표"**에 둔다. 한밤 12.x에서의 실제 기록 동작은 [SPIKES S1](SPIKES.md#s1-로그-기록-지연과-뭉침-측정)에서 실측해 확정한다.

## 1. 용어

| 용어 | 뜻 |
|---|---|
| 풀(Pull) | 채점 단위가 되는 전투 구간. 레이드는 `ENCOUNTER_START`~`ENCOUNTER_END`, 허수아비·야외는 전투 활동 기반 분할 ([ARCHITECTURE §4.4](ARCHITECTURE.md#44-pull-segmenter-풀-분할기)) |
| 결정 지점(Decision Point, DP) | 플레이어가 GCD 스킬을 고를 수 있었던 시점. 실제 시전 1회 또는 "놀린 GCD" 1회에 대응 |
| 판정(Verdict) | DP 하나에 대한 결과 (일치/허용/경미/실수/공백/제외/불확정) — [SCORING_SPEC §2](SCORING_SPEC.md#2-판정-분류) |
| 정규화 이벤트(CombatEvent) | 로컬 로그·WCL 양쪽에서 같은 모양으로 변환된 이벤트 ([ARCHITECTURE §3.1](ARCHITECTURE.md#31-combatevent-정규화-이벤트)) |
| 채점 결과(ScoringResult) | 엔진이 만드는 구조화 결과. 오버레이·AI 리포트·비교의 유일한 입력 |

## 3. 비기능 요구사항 (NFR)

### 3.1 지연

지연은 세 구간으로 나눠 관리한다. 엔진이 통제할 수 있는 것은 B, C뿐이다.

- **A. 로그 기록 지연**: 전투 종료부터 그 전투의 줄이 파일에 다 쓰일 때까지. WoW 클라이언트 동작에 좌우된다 → [SPIKES S1](SPIKES.md#s1-로그-기록-지연과-뭉침-측정)에서 실측
- **B. 엔진 지연**: 풀 종료가 확인된 순간(마지막 줄 도착 + 안정화 대기)부터 오버레이에 규칙 기반 결과가 뜰 때까지
- **C. AI 지연**: 규칙 기반 결과가 뜬 뒤 AI 빠른 요약이 붙을 때까지

| ID | 요구사항 | 목표 |
|---|---|---|
| NFR-L1 | 엔진 지연 B (p95), 5분 레이드 풀 기준 | ≤ 1 s (재생 처리 + 판정 + 렌더) |
| NFR-L2 | 풀 종료 안정화 대기: 일괄 기록이 끝났다고 보는 기준 (파일 크기 변화 없음 지속 시간) | 기본 500 ms, S1 결과로 조정 |
| NFR-L3 | A + B (전투 종료 → 오버레이 결과) | 목표 p95 ≤ 3 s. **A는 S1 실측으로 확정**, 기록이 수십 초 이상 늦는 콘텐츠는 "지연 표시" 후 도착 시 갱신 |
| NFR-L4 | C: AI 빠른 요약 | p95 ≤ 8 s, 목표 ≤ 5 s ([SPIKES S6](SPIKES.md#s6-claude-api-지연비용한국어-품질)) |
| NFR-L5 | 상세 해설 | 스트리밍 첫 토큰 ≤ 5 s, 완료 ≤ 60 s |
| NFR-L6 | (선택 기능) 전투 중 갱신이 켜져 있고 데이터가 도착하는 경우, 줄 도착 → 지표 반영 | ≤ 200 ms + 판정 보류창(기본 2 s, [SCORING_SPEC §6.2](SCORING_SPEC.md#62-지연-판정lookahead)) |

> 목표는 "전투 중 실시간"이 아니라 **"전투가 끝나면 몇 초 안에 게임 화면 위에서 채점표를 본다"**이다. 이 방식은 WCL 같은 사후 분석 도구와 같은 위치에 있어 정책상 가장 안전하다 ([RISKS P-1](RISKS.md#정책-리스크)).

### 3.2 정확도

## 4. 제약 (ToS·정책) — 모든 요구사항보다 우선

| ID | 제약 | 설계상 보장 방법 |
|---|---|---|
| C-1 | 게임 메모리 읽기, 렌더링 인젝션(DLL·그래픽 훅), 키 입력 시뮬레이션, 화면 픽셀 판독 금지 | 해당 API를 쓰는 의존성 금지 목록 유지. 오버레이는 별도 최상위 창일 뿐 게임 프로세스에 접근하지 않음 |
| C-2 | 데이터 소스는 전투 로그 파일과 WCL API뿐 | 입력 어댑터는 `LogFileSource`, `WclSource` 두 가지만 존재 |
| C-3 | 오버레이는 평가(점수·일치율·놓친 횟수)만 표시, 실시간 지시 금지 | `OverlayViewModel` 스키마에 "다음 스킬" 필드 없음. 전투 중 개별 DP의 "정답 스킬"도 표시하지 않음 (기본값, [결정 필요 D-4](#6-결정이-필요한-항목)) |
| C-4 | 오버레이는 포커스와 입력을 절대 가로채지 않음 | `WS_EX_TRANSPARENT | WS_EX_NOACTIVATE | WS_EX_LAYERED | WS_EX_TOOLWINDOW` 강제, 상호작용은 별도 제어판 창에서만. 전역 단축키는 기본 비활성 |
| C-5 | 게임에 어떤 입력도 보내지 않음 | `SendInput`, `PostMessage`류 사용 금지 (코드 리뷰 체크리스트) |
| C-6 | 로그 기록 방식(전투 중 버퍼링)을 우회하지 않음 | 전투 중 `/combatlog` 토글 유도, 기록을 앞당기는 애드온·매크로·설정 안내를 하지 않음. 들어온 데이터만 처리 |

## 5. 범위 밖 (Out of Scope)

- 생존 외 전문화 (구조만 확장 가능하게 설계)
- MVP의 광역(2+ 대상) 채점, 쐐기돌 채점 → M7 이후
- 실시간 행동 지시, 다음 스킬 예측 표시, 소리·알림으로 시전 유도
- 게임 메모리·화면·네트워크 패킷 판독, 애드온과의 연동(한밤 비밀 값 우회 목적 포함)
- 레이드 전체 분석(다른 플레이어 채점), 탱커·힐러
- WCL 자동 업로드 (WCL 공식 업로더 사용)
- 클래식 계열 클라이언트
- 설치 관리자, 자동 업데이트, 다중 사용자 키 관리, 공개 배포 (본인 1인 전용)
- DPS 절대값 예측, 시뮬레이션 대체 (SimC 자체를 대체하지 않음)

## 6. 결정이 필요한 항목

이 문서에서 생긴 결정 항목. 전체 목록은 [ROADMAP §5](ROADMAP.md#5-결정이-필요한-항목-전체-목록)에 모아 둔다.

- **D-3** 전투 중 갱신(FR-31)을 아예 만들지 않을지, 기본 꺼짐으로 둘지. 기본안: 기본 꺼짐 선택 기능으로 두되 S1 결과 데이터가 전투 중에 안 오면 구현하지 않음.
- **D-4** 전투 중 오버레이에 직전 실수의 내용("X 대신 Y")을 보여줄지. 기본안: 전투 중에는 개수만, 내용은 풀 종료 후에만.
- **D-5** 상세 해설 기본 모델: Sonnet 5.5(기본) vs Opus 5.5.
- **D-6** 전역 단축키 허용 여부 (기본: 사용 안 함, 트레이·제어판으로만 조작).
