# M0 검증 안내

목적은 세 가지다. ① 비슷한 애드온이 이미 충분한지 ② 애드온이 실제로 어떤 값을 읽을 수 있는지 ③ WCL API가 예상대로 동작하고 점수를 얼마나 쓰는지. 결과를 보고 M1 진행 여부와 분석 항목을 확정한다.

모든 명령은 PowerShell에서, 저장소 폴더(예: `C:\dev\RotationCoach`)에서 실행한다. 먼저 최신 내용을 받는다.

```powershell
cd C:\dev\RotationCoach
git pull
```

## 1. 기존 애드온 2종 써 보기

CurseForge에서 **Midnight Sensei**와 **RecommendedStats**를 설치하고, 허수아비에서 3분쯤 친 뒤 각각의 결과 화면을 본다. 아래를 메모해 준다.

| 확인할 것 | Midnight Sensei | RecommendedStats |
|---|---|---|
| 오프닝(첫 8~10시전)을 기준 순서와 비교해 주는가 | | |
| "어느 시전이 무엇과 달랐는지"까지 보여 주는가, 아니면 점수·등급만인가 | | |
| 상위 로그 대비 쿨기 타이밍·분당 시전 수를 보여 주는가 | | |
| 한국어로 나오는가 | | |
| 허수아비에서도 동작하는가 | | |
| 쓰면서 부족하다고 느낀 점 | | |

둘 중 하나로 충분하다면 여기서 멈추는 것이 맞다.

## 2. 검증용 애드온 (RotationTeacherProbe)

전투 중에는 기록만 하고 화면에 아무것도 띄우지 않는다. 전투가 끝나면 채팅창에 한 줄 요약만 나온다.

### 설치

WoW를 끈 상태에서, 저장소의 `RotationTeacherProbe` 폴더를 애드온 폴더에 연결한다 (연결해 두면 `git pull`만으로 갱신된다). WoW 설치 경로가 다르면 `$WOW`를 바꾼다.

```powershell
$WOW = "C:\Program Files (x86)\World of Warcraft\_retail_"
cmd /c mklink /J "$WOW\Interface\AddOns\RotationTeacherProbe" "$PWD\RotationTeacherProbe"
```

권한 오류가 나면 폴더를 그대로 복사해도 된다: `Copy-Item -Recurse RotationTeacherProbe "$WOW\Interface\AddOns\"`.

게임 접속 후 캐릭터 선택 화면의 애드온 목록에서 "Rotation Teacher Probe (M0)"가 켜져 있는지 확인한다. "구버전"으로 표시되면 "구버전 애드온 사용"을 체크한다.

### 게임 안에서 할 일

주로 하는 사냥꾼 전문화로 진행한다. 전문화를 바꿔 가며 해도 된다 (전문화별로 따로 기록된다).

| # | 상황 | 방법 | 알고 싶은 것 |
|---|---|---|---|
| A | 도시 허수아비 | 평소 로테이션 2~3분. 2번 반복 | 시전 기록, 쿨 상태, 반짝임, 전투 후 피해 미터 |
| B | 허수아비, 전투 전 시전 포함 | 전투 시작 몇 초 전에 스킬을 하나 쓰고 시작 | 전투 전 시전이 잡히는지 |
| C | 던전 (추종자 던전 가능) | 잡몹 구간 + 보스 1마리 | 인스턴스 안에서 달라지는 점 |
| D | 레이드 보스 (공격대 찾기 가능) | 보스 1마리 | 레이드에서 시전 기록이 되는지 (가장 중요) |
| E | 쐐기돌 (가능하면) | 아무 구간 | 쐐기에서 달라지는 점 |

- 전투가 끝날 때마다 채팅창에 `[RT Probe] 세션 #N 저장: …` 한 줄이 나와야 한다.
- `/rtp last` 를 치면 방금 전투에서 무엇이 비밀 값이었는지 요약을 볼 수 있다.
- 다른 명령: `/rtp` (상태), `/rtp off` / `/rtp on` (기록 끄기/켜기), `/rtp clear` (전부 지우기).
- Lua 오류 창이 뜨면 내용을 복사해 둔다.

### 결과 넘기기

기록은 `/reload` 또는 접속 종료 때 파일로 써진다. 모든 상황을 마친 뒤 `/reload` 한 번 하고 게임을 끈 다음, 아래 파일을 넘겨 준다.

```
<WoW>\_retail_\WTF\Account\<계정 이름>\SavedVariables\RotationTeacherProbe.lua
```

- 넘기는 방법: 이 파일을 저장소의 `m0\` 폴더에 복사해 커밋·푸시하거나, 대화에 첨부한다.
- 이 파일에는 캐릭터 이름·서버·계정 정보가 들어가지 않는다. 들어가는 것은 직업·전문화 번호, 주문 ID와 주문 이름, 시각, 쿨 상태, 보스 이름과 ID, 대상 NPC 번호다.

## 3. WCL API 확인

1. https://www.warcraftlogs.com/api/clients 에서 **새 클라이언트를 만든다.** 이름은 `RotationTeacher`, 리디렉션 URL은 `http://localhost` 로 두고, **PKCE 관련 체크 항목은 해제**한다 (화면의 정확한 문구는 확인하지 못했다). 만들면 클라이언트 ID와 시크릿이 나온다. 시크릿은 대화나 저장소에 붙여넣지 않는다.
2. 값을 암호화해 저장한다. 입력 내용은 화면에 보이지 않는다.
   ```powershell
   powershell -ExecutionPolicy Bypass -File tools\Save-WclCredential.ps1 -Kind confidential
   powershell -ExecutionPolicy Bypass -File tools\Save-WclCredential.ps1 -Show
   ```
3. API를 호출해 본다 (전문화는 `BeastMastery`, `Marksmanship`, `Survival` 중 하나).
   ```powershell
   powershell -ExecutionPolicy Bypass -File tools\Test-WclApi.ps1 -Spec Survival
   ```
   출력 전체를 복사해 알려 준다. 플레이어 이름은 출력되지 않는다.
4. API 약관을 브라우저로 읽어 본다: https://www.archon.gg/wow/articles/help/rpg-logs-api-terms-of-service — 특히 캐시 보관과 재배포 조항. 개인용으로만 쓸 계획이지만, 받은 데이터를 로컬에 저장해 두는 것이 허용되는지 확인이 필요하다.

두 PowerShell 스크립트는 Windows에서 아직 실행해 보지 못했다. 오류가 나면 메시지를 그대로 알려 준다.

## 4. 판정 기준

| 결과 | 다음 |
|---|---|
| 기존 애드온으로 충분 | 중단 |
| D(레이드)에서 내 시전의 주문 ID가 기록됨 | 계획대로 M1 진행 |
| 레이드에서 주문 ID가 비밀로 나옴 | 범위를 허수아비·던전으로 줄이고, 레이드는 전투 로그 파일 방식으로 재검토 |
| 쿨 상태·반짝임이 전투 중 읽힘 | 분석 항목 3·5·6(쿨기, 충전 넘침, 발동 효과) 유지 |
| 읽히지 않음 | 해당 항목을 시전 기록 기반 추정으로 바꾸거나 제외 |
| WCL 랭킹 + 시전 조회가 건당 수 점 이내 | M2 계획 유지 |
| 한도가 너무 작거나 약관상 저장 불가 | 기준 데이터는 SimC + 가이드 메모 위주로, WCL은 수동 참고로 축소 |
